{% comment %} Keeps navigation that starts inside one of the app's own iframes IN the frame. A framed page (the conversations workspace's record pane, the follow-ups dashboard's detail pane) shows no chrome of its own, because its host already has it. Any plain link or form on it, followed as written, loads the next page WITH its sidebar and bottom bar - a second nav bar inside the pane. The links we know about carry `frame_query` on the server; this is the net under the ones we do not, so a page added next month is covered without anybody remembering to. How: on click / submit, a same-origin link or form action that does not already say `frame` gets this page's frame context (frame, hidetabs, source) added. Left alone on purpose: target="_top" / "_blank" (a deliberate break out of the frame), in-page anchors, and mailto: / tel: / javascript: links. Redirects are covered server-side by FrameContextMiddleware. Rendered only when `frame_query` is set, so an ordinary page carries none of it. {% endcomment %} {% if frame_query %} {% endif %}
