WHAT: (1) puts DESCRIPTION before QTY in every item row and , since the paper reads Description | Qty | Unit price | Total, where the sectioned sheet it rides reads Qty first; (2) relabels the group heading's placeholder, because on this sheet the heading is a blank separator row and its title is never printed; (3) mirrors the live grand total (#t-grand) into the black figure box at the foot ([data-fs-grand]). WHY here and not in each page's JavaScript: the quote editor and the template builder build rows in two different ways (string templates vs a formset prototype), and a server-rendered sheet arrives already built. One observer on the sheet catches every row however it got there, so neither editor's own code carries a fix-and-supply branch that could drift from the other. Rows and tables already rendered in paper order carry data-fs-ordered and are left alone (the read-only view does this). HOW: runs once over what is on the page, then a MutationObserver on each .bq-sheet--fs handles rows added later (the editor builds its rows on DOMContentLoaded, after this script has parsed). Cells are found by position and moved once; the editors read cells by class (.bq-qty, .bq-desc, field names), never by index, so the move does not touch what they save.
