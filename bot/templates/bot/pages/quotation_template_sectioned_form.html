The rule is the one the flat builder already follows — building a template is building a quote, so the builder is the quote editor's layout — applied to a tenant whose quote editor is `quote_sectioned_form.html`. That means this screen IS their quote document: their own letterhead, the numbered sections each with a SUB-TOTAL, the QTY | DESCRIPTION | UNIT PRICE | TOTAL PRICE columns in the sheet's own order, the labour / transport / SUB-TOTAL / VAT / GRAND TOTAL block, and the banking and signature foot. Same tenant switch as every other quote screen (`is_sectioned`), which is tenant data and never a slug check, so this sheet can never render for a tenant it does not belong to. What differs is only what a template does not have: * no client. The `.bq-meta` grid holds the TEMPLATE's own identity instead — name, project type, description — in the same two-column shape a quote's DATE / CLIENT / CONTACT / ADDRESS / EMAIL uses. * no per-job figures. VAT, the deposit and the payment terms are the business's own defaults from their Profile, shown where the quote will carry them but not editable here; a discount is per job and the paper document has no such row, so there is none. * no send. A template is never delivered to anybody, so the bar closes on Cancel / Add section / Save. The items are the same Django FORMSET the flat builder posts (`items-0-description` and so on) — only the markup around those inputs is the sheet's.
