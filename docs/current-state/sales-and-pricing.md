Portfolio/catalogue and every pricing rule (price close, budget ladder, replacements, materials lists).

### Portfolio / catalogue (`bot/portfolio_catalog.py`)
- Static list of previous-work pieces (title, "from" price, description, keywords). `match_portfolio_item` returns a single item only when the message clearly references one piece, else `None` → whole-gallery send; `_describe_work_image` derives a per-image description (curated title for catalogued files, tidied filename otherwise) for the media index. Prices are the business's own "from" rates from `bot/sales_profiles/homebase.md` (source of truth — keep in sync, never invent figures); captions are title-only.

### Pricing & sales (`bot/views/plumbot/response_mixin.py`)
- `detect_service_inquiry` → priceable intent; `handle_service_inquiry(intent, message)` builds the reply from a `structured_pricing` table keyed by intent (the message is used only for language detection). `generate_pricing_overview` gives the full menu; `compose_multi_answer` answers 2+ info questions in one reply.
- Pricing is gated: don't volunteer price when unasked, don't re-send an already-sent intent, and don't price a message that's a project description / booking-capture answer.
- **The price close is a soft value yes, and a no climbs the budget ladder** (owner rule, 2026-09-19, replacing the all-in reframe). "Bathroom renovation starts from US$900 ... What is your budget?" read as a demand and the lead answered "Will let you know". `_price_tiedown(language, subject)` is now "Does that sound like something you'd be willing to invest in for a new bathroom?", with the subject taken from the intent priced this turn (`_pricing_subject`, set in `handle_service_inquiry`), else the lead's service type, else none (`_invest_subject` / `_INVEST_SUBJECTS`). A no (`_is_budget_decline`) gets `_build_budget_ask` ("No problem. How much were you hoping to invest in a new bathroom?"). Their figure (`_budget_figure`: "about 500", "$1,200", "1.5k") gets `_build_budget_options_reply`: the tenant's OWN price rows for that subject at or under it, closest first, three at most; nothing fits names the most affordable option; no rows names no figure but theirs. **Never a discount.** Both rungs run in webhook STEP 1a and in `generate_response`, and **`controller.decide_move` stands aside after either question** (`_answering_our_budget_question`), because the controller runs BEFORE STEP 1a and would otherwise answer a "no" with the fee objection. The subject for rungs 2 and 3 is read back off our own last message (`_subject_of_our_last_turn`), so nothing is stored. Two nets for the model paths: `soften_budget_question` in `finalise_outbound` swaps any whole question sentence mentioning the budget (English only) for the tie-down, and `response_check._fences_hold` rejects a refinement that adds "what is your budget". The retired "with your budget" wording is still recognised (`_LEGACY_PRICE_TIEDOWN_SIGNATURES`) so a lead mid-conversation still climbs the ladder. Pinned by the `budget ladder` / `budget options` / `budget figure` cases in TEST 0 and `scenarios/budget_ladder_soft_close.txt`.
- **"Replace my old X with a new one" is priced as the NEW fixture** (owner rule, 2026-09-18): supply, install and the mixer where that fixture takes one (basin, vanity: basin mixer; built-in tub: bath mixer; shower: shower mixer; kitchen sink: sink mixer), then the all-in total and the budget tie-down. `_replacement_price_reply` runs FIRST in `_handle_service_inquiry_impl`, ahead of any carried intent, and takes the fixture from the customer's OWN words (`_replacement_fixture`): the classifier maps basin to vanity, so a basin replacement used to come back priced as a vanity unit. Supply and install come off the tenant's price row; the mixer off that row's `parts`, else the tenant's own quote lines (`materials_list.tenant_price_book`), and **no mixer figure means no mixer line**. A tub also offers the freestanding build (its mixer is inside that figure). Replacing a PART (seat, element, valve, head, washer) is a repair and stays on the repair path; two fixtures go to the combined path. Pinned by the `replace:` cases in TEST 0 and `scenarios/replace_old_fixture_prices_the_new_one.txt`.
- **A photographed materials list is priced from the tenant's OWN quote lines** (`bot/materials_list.py`, owner decision 2026-09-18). Vision's one-line description says "written materials list"; only then a second, `detail=high` call (`transcribe_materials_list`) reads every line onto the photo turn as the `materials_list` JSON key. The ack asks supply-only or supply-and-fit and names no figure. **Nothing is priced until the lead asks** — `_materials_list_price_reply` runs just before the FAQ layer, only on a price or labour question, and never when the message names a fixture the list lacks. Unit prices come from the tenant's own `QuotationItem`s (newest first), then its own non-global templates, then `TenantPriceItem.supply` for a fixture line; **a line nothing matches is listed for the quote, never guessed**. Matching is strict because a wrong number is worse than none: sizes and item nouns must agree exactly, male/female and single/double must agree even when one side is silent, and "(cap)" is a brand, not a noun. The plumber's own shorthand is read too (c.f.i / c.m.i, "soldering flux", "25mm vsp", "tub combination p-trap"), and a size-less list line takes a sized quote line only when every sized variant agrees on price. **The reply is the OWNER-APPROVED copy (2026-09-18) and `build_list_price_reply` reproduces it:** "These are the prices I have for now on your list:", one `qty x item: total (unit each)` line per priced item with brand notes stripped for the customer (`display_item`), "That comes to about US$X for these items.", then "For everything else on the list and the final price, we would need to come and see the place. That also lets us give you an accurate figure for the labour. Because it's all one job, the labour usually comes in lower than pricing each fitting on its own.", closing "When would suit you for us to come and have a look, this week or next week?". **Unpriced items are never listed** (the owner does not want "still getting prices"). Contextual variations only: all priced drops "everything else", nothing priced goes straight to the visit with no figure, rough fixture labour lines only when they asked about labour, a booked lead is told the rest is done at the visit instead of being asked for a day, Shona for a Shona lead, and a tenant that CHARGES for the visit gets its fee sentence once before the close. The reply skips the model reader (`check=False`) and the chain's fee note (`finalise_outbound(visit_note=False)`, default True for everything else), because that note REPLACES the availability question and would swap out the approved close. Pinned by the `materials:` cases in TEST 0 and `MaterialsListPriceBookTests`.
- **The memory check keeps paragraph breaks.** `strip_known_questions` rejoined every reply's sentences with a single space, even when it dropped nothing, so any `\n\n` after a full stop was flattened in EVERY outbound message. It now returns an untouched reply as-is and keeps each sentence's own separator when it does drop one.
